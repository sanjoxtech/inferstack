## Qualification decision — sandbox coverage from CI (2026-11-09)

Decision (project owner, 9 November 2026): on a GPU host that cannot run the
filesystem sandbox (Colab cannot create the namespaces bwrap needs), the sandbox
tests may be covered by GitHub Actions CI **for the same commit**. Implemented in
`scripts/v2_qualify.py` (`apply_sandbox_evidence`, `--sandbox-evidence`), with
`scripts/ci_evidence.py` (fetch check runs for a commit) and `scripts/requalify.py`
(apply to an existing result without modifying it). The evidence is accepted only when
the commit matches, both CI suite jobs (`CPU conformance (py3.11)` and `(py3.12)`)
concluded `success`, and the test_suite gate was blocked solely by sandbox skips.
Real failures, other skips and other required gates are never excused
(`tests/test_sandbox_evidence.py`).

Applied to the 09:07 UTC run at `d33b470`: CI run 42588868475 succeeded on that commit
(both suite jobs green). Result: **verdict `qualified`, profile `a100`**, no blocking
gates. Files: `evidence/colab-a100-d33b470-qualification.json` (original, unchanged),
`evidence/ci-d33b470.json` (CI check runs) and
`evidence/qualification-with-ci-evidence.json` (amended verdict with job links).

Scope: A100-SXM4-40GB, BF16, native engine, Qwen3.5-2B-Base pinned revision, this
torch/CUDA/Triton stack. Not covered: vLLM/SGLang conformance, T4, other GPUs, any
performance claim (lanes remain `inconclusive_single_run` until repeated).
