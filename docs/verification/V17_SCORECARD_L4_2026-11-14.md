## Reading

- The lane delivers what the model-step benchmark predicted. Single-stream decode drops
  from 30.0 to 16.9 ms/token (vLLM 15.8, SGLang 15.6), and output throughput is 1.5–1.85×
  native_full for interactive and moderate traffic.
- The remaining gap to vLLM/SGLang is now dominated by prefill, not decode:
  - TTFT is 4–8× vLLM on moderate and prefill_heavy cases, unchanged by the lane.
  - Decode ms/token rises under prefill-heavy load (88.7 ms at c16) because decode steps
    share the GPU with the Transformers chunked-prefill path.
  - This is exactly the N3 target (token-budget scheduler + one fused GDN prefill
    primitive, docs/LLAMA_CPP_INTEGRATION_PLAN.md).
- The single TTFT regression (prefill_heavy c16, +3%) and the memory increase are the
  costs of the lane. Neither outweighs the 16/16 throughput and latency wins.
- Quality is evaluated separately (scorecard claim). The lane matches the Transformers decode path
  token for token in the CPU engine tests (tests/test_qwen_static_lane.py). The earlier
  model-step L4 run showed ≥0.984 greedy agreement in BF16.

## Decision

Keep `production-v1.7.0` (static decode lane) as the native default candidate. Next: N3
prefill (token-budget scheduling + fused GDN chunked-prefill primitive), judged on the same
full scorecard.
