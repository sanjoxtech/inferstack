The 27 excluded posts do not become requirements. Adding a lead to this table is not a commitment to implement it.

## Work still needed before saying “all research is deeply integrated”

1. **Capture usable evidence.** For selected retained posts/links, store permitted text or extracted claims, retrieval time, source URL, source commit and artifact digest. Record unavailable/deleted sources honestly; do not invent missing text from a URL.
2. **Classify and deduplicate.** Map each selected claim to a technique/problem, separate repeated promotion from independent evidence, and record adopt/experiment/defer/reject with a reason. The current permalink ledger cannot answer those questions alone.
3. **Audit implementable candidates.** Inspect the actual selected code path, dependencies/license, supported engine/model/GPU and benchmark protocol. A README or metadata lookup alone does not finish this step.
4. **Create versioned experiment manifests.** For the initial speculation or other chosen technique, define source identities, baseline, workload/cache state, target hardware, gates, budgets and stopping rules. Connect them to the bounded implementer and trusted verifier.
5. **Ingest and retrieve.** Use the existing evidence/artifact store through H1/H2, with applicability and cross-campaign retrieval. Repository Markdown does not automatically become agent memory.
6. **Reproduce and decide.** Run independent target-environment measurements and store reject/inconclusive as well as positive results. A technology becomes qualified only after the relevant evidence passes; no collected external speedup is already an InferStack performance result.

First fix the source review's evidence/execution/recovery defects, then implement H1/H2 and select one compatible speculation or configuration experiment for H3/H4. Keep experimental memory formats, additional engines and persistent workers queued until their applicability and value are demonstrated.
